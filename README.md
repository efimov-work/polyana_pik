# Поляна Пик

Одностраничный сайт по продаже апартаментов, пентхаусов, шале и коммерческих помещений в комплексе «Поляна Пик» в Красной Поляне.

Перенос дизайн-макета (`Polyana-Peak-landing.html`) на Next.js. Макет адаптивный, поэтому страница собрана одним деревом компонентов, без отдельных десктопной и мобильной версий. Стили макета перенесены дословно, инлайном, как в исходнике. В `globals.css` лежит только то, чего в макете не было: поля ввода, кнопки, состояния форм и анимации первого экрана.

## Стек

- Next.js 16 (App Router, standalone-сборка)
- React 19, TypeScript
- Docker

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000
```

Прод:

```bash
npm run build
npm run start
```

Docker:

```bash
cp .env.example .env
docker compose up --build
```

## Переменные окружения

Смотрите `.env.example`.

| Переменная | Когда читается | Назначение |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | сборка | канонический адрес сайта: метаданные, микроразметка, `robots.txt`, `sitemap.xml` |
| `YANDEX_VERIFICATION` | сборка | код подтверждения прав в Яндекс.Вебмастере |
| `GOOGLE_SITE_VERIFICATION` | сборка | то же для Google Search Console |
| `TELEGRAM_BOT_TOKEN` | запуск | токен бота для доставки заявок; без него заявка только пишется в журнал |
| `TELEGRAM_CHAT_ID` | запуск | чат или группа, куда бот шлёт заявки |
| `TELEGRAM_THREAD_ID` | запуск | тема супергруппы-форума; пусто - бот пишет в общую ленту |
| `TRUST_PROXY` | запуск | `1`, только если перед приложением стоит доверенный прокси |
| `LEADS_DATA_DIR` | запуск | каталог с журналом заявок, в докере том `leads-data` |
| `WEB_PORT` | запуск | порт хоста в docker compose, по умолчанию 3000 |

Переменные с пометкой «сборка» Next подставляет в код при `npm run build`, поменять их на запущенном контейнере нельзя. В `docker-compose.yml` они уходят в `build.args`, так что смена домена или кода вебмастера - это `docker compose up --build`.

**Домена пока нет.** Без `NEXT_PUBLIC_SITE_URL` канонический адрес, карта сайта и микроразметка указывают на `http://localhost:3000`. Перед выкладкой адрес нужно задать. Кириллический домен можно писать как есть: он приводится к punycode через `new URL().origin`.

## Превью на GitHub Pages

```bash
npm run pages
```

Скрипт `scripts/gh-pages.sh` собирает статическую версию во временной копии проекта и пушит её в ветку `gh-pages`. Адрес: `https://<владелец>.github.io/<репозиторий>/`, владелец берётся из `origin`; если репозиторий переехал, его можно задать явно: `PAGES_OWNER=efimov-work npm run pages`. Рабочее дерево и `.next` не трогаются.

Отличия от прод-сборки:

- `output: 'export'` и `basePath` из имени репозитория (`STATIC_EXPORT=1`, `NEXT_PUBLIC_BASE_PATH`); пути к картинкам идут через `asset()` из `src/lib/asset.ts`;
- приёма заявок нет: на Pages нет сервера, форма покажет ошибку отправки;
- `SITE_NOINDEX=1`: `noindex, nofollow` в мета-тегах и `Disallow: /` в `robots.txt`, чтобы превью не попало в выдачу дублем будущего домена;
- счётчик Метрики и коды вебмастеров отключены.

В настройках репозитория (Settings → Pages) источник должен быть `Deploy from a branch`, ветка `gh-pages`, папка `/`. Для приватного репозитория Pages работает только на платном тарифе владельца.## Структура

## Анимации

Логика перенесена из скрипта макета (`initAnims`), селекторы и тайминги те же.

- Первый экран: фото плавно отъезжает с масштаба 1.18 и дальше медленно дрейфует, шапка, плашка, заголовок, текст и форма появляются по очереди. В макете это запускалось скриптом; здесь сделано на CSS, чтобы анимация шла с первой отрисовки и текст не мигал после гидрации.
- Ниже первого экрана: заголовки и дочерние блоки сеток поднимаются при прокрутке, фотографии открываются шторкой снизу вверх. Скрываются только блоки ниже экрана на момент загрузки, поэтому без JavaScript вся страница видна сразу.
- Блок с логотипом: линия гор прорисовывается, логотип проявляется, горы сдвигаются вслед за прокруткой.
- Две фотографии в блоке «Почему сейчас» двигаются с параллаксом.

Что изменено относительно макета: вместо бесконечного цикла `requestAnimationFrame` проверка идёт по событию прокрутки, не чаще кадра; дрейф фото первого экрана встаёт на паузу, когда экран ушёл из вида; при `prefers-reduced-motion` анимации отключены.

## Заявки

Форм две: на первом экране (только телефон) и в блоке консультации (имя, телефон, цель покупки). Кнопка «Узнать цену» в карточке планировки прокручивает к форме консультации и добавляет в заявку выбранную планировку.

Телефон обязателен. Российский номер набирается по маске `+7 (___) ___-__-__` и должен быть полным; номер с другим кодом страны вводится без маски, 10-15 цифр. Состояния формы: отправка, ошибка с текстом под кнопкой, успех. Скрытое поле-ловушка отсекает ботов: заполненная заявка получает `ok`, но никуда не уходит.

Заявка дописывается в `LEADS_DATA_DIR/leads.jsonl` до попытки отправки в Telegram, недоставленные дублируются в `leads-undelivered.jsonl`. Ошибки доставки посетителю не показываются: заявка уже принята. В логе сервера они видны строкой `lead not delivered to telegram`.

```bash
docker compose exec web cat /app/.data/leads-undelivered.jsonl
```

Частота ограничена по номеру (3 в час), по источнику (10 в час, только при `TRUST_PROXY=1`) и глобально (120 в минуту).

### Telegram

1. У `@BotFather`: `/newbot`, токен в `TELEGRAM_BOT_TOKEN`.
2. Добавить бота в рабочую группу и написать там любое сообщение.
3. `npm run tg chats` - напечатает готовую строку `TELEGRAM_CHAT_ID=...`, для групп с темами ещё и `TELEGRAM_THREAD_ID=...`.
4. `npm run tg test` - в группу придёт пробная заявка в том же виде, в каком приходят настоящие.

Ещё команды: `npm run tg info` - кто этот бот, `npm run tg webhook-delete` - снять вебхук, если он мешает `getUpdates`.

## SEO

Тексты метаданных и сборка микроразметки лежат в `src/lib/seo.ts`. Адрес и список сервисов берутся из `src/lib/content.ts`, из тех же констант, что рисуют страницу.

Выдаётся:

- `title`, `description`, `canonical`, `keywords`;
- Open Graph и Twitter Card с превью 1200x630 (`src/app/opengraph-image.jpg`), снятым с первого экрана;
- `robots.txt` с `Sitemap:` и `Host:`, `/api/` закрыт;
- `sitemap.xml` с фотографией первого экрана, `lastmod` по дате сборки;
- логотип 1000x1000 на тёмном фоне (`public/logo.png`): в микроразметке и в карте сайта;
- иконки и `manifest.webmanifest`: `icon.png` и `apple-icon.png` с полным логотипом, `favicon.ico` и `icon.svg` с линией гор из него, потому что надпись в 16-32px не читается;
- `max-image-preview:large` для Googlebot;
- мета-теги подтверждения прав, если заданы `YANDEX_VERIFICATION` и `GOOGLE_SITE_VERIFICATION`.

Микроразметка - один `@graph`: `WebSite`, `WebPage` и `ApartmentComplex` с адресом, логотипом и двенадцатью сервисами. Телефона, цен и организации-продавца в разметке нет: телефон на сайте пока заглушка, цены выдаются по запросу.

Скорость: фото первого экрана - обычный `<img>` с `fetchpriority="high"` и вариантом 1200px для телефонов, всё ниже грузится лениво. Фотографии в макете были CSS-фонами; здесь это `<img>` с `alt`, чтобы они попадали в поиск по картинкам. Изображения переведены в WebP: 20 МБ исходников (из них 10,5 МБ - фото первого экрана) стали 2 МБ. Шрифты Tenor Sans и Manrope раздаются с того же домена через `next/font`.

## Отличия от макета

- Заставка с прорисовкой гор при загрузке не перенесена: в скрипте макета она отключена и сразу удаляется.
- Переключатель шрифтовых пар из редактора макета не перенесён, оставлена пара по умолчанию: Tenor Sans и Manrope.
- Фотографии, которые макет грузил с polyanapeak.ru (первый экран, фасад, генплан, логотип), лежат в проекте.
- Поля форм, чипы и кнопки в макете нарисованы блоками; здесь это настоящие элементы форм. Шрифт в поле телефона первого экрана 16px вместо 15px, иначе iOS приближает страницу при фокусе.
- Фильтр планировок работает: «1 спальня» и «Двухуровневые».
- В карточках планировок строка с ценой прижата к низу, чтобы кнопки в ряду стояли на одной линии.
- Телефон в шапке, блоке консультации и подвале - ссылка `tel:`.

Высота страницы совпадает с макетом до пикселя на 1440px (9428px) и 390px (16254px), сверено скриншотами.
